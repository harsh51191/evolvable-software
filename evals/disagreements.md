# Rater disagreements

Every disagreement between raters, every missed expectation in an evaluation case, and every error found by re-reading a published assessment is logged here, with its cause and what it changed. `README.md` in this folder explains the process.

All raters so far are AI models. "First" is the field-test rating (Claude, single rater); "second" is a blind Claude rater; "third" is a blind ChatGPT (Codex) rater that read the code through GitHub's web pages, so its absence findings are bounded by the files it opened. The study is `assessments/2026-09-field-test/second-rating/`. Scope-fact and applicability rows show `n/a` where a scope fact switched the criterion off.

## Status

Three definitions were tightened in v0.7 because of the 14 October study: LRN-08 for products that produce no learned or AI-made changes, `multi_tenant`, and `code_release_path` with `agent_mutations`. The evaluation cases pin each of them: `static-notes` expects LRN-08 0 and `code_release_path` false for ordinary CI; `rules-desk` expects `multi_tenant` false for one company and records LRN-08 as a range of two readings; `drafting-desk` expects `agent_mutations` true for AI drafts awaiting approval, `code_release_path` false for AI-written rules, and `multi_tenant` true for several customer organisations.

Still open: Dify backup documentation, the third rater's web-only readings, `hosted_service` for a single-user daemon, and n8n `evolution_auto_apply`.
